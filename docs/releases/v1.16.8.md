# Adaptive RoboVacs v1.16.8

This standalone performance release reduces work generated by unchanged Home
Assistant state while preserving all public entities, controls, scheduling
rules, and safety gates.

- The global `state_changed` listener is replaced by a dynamically rebound
  subscription to discovered occupancy, vacuum, readiness, diagnostic, battery,
  cleaning-time, and profile entities. Same-state and irrelevant attribute-only
  events are ignored; profile-option changes refresh capabilities.
- Meaningful transitions retain FIFO side effects, but settled evaluations are
  coalesced, with one follow-up when more input arrives during an evaluation.
- Ordinary evaluations no longer scan registries. Setup, post-start vendor
  settling, relevant registry/label/area/device events, capability changes, and
  explicit refreshes own discovery, with burst coalescing and snapshot publication
  before dynamic platform discovery signals.
- Durable-state fingerprinting skips Store writes caused only by evaluation
  timestamps or previews. Durable mutations persist immediately, while migration,
  Repair, and dispatch checkpoints always force and await a completed write.
- Typed snapshot deltas preserve the immutable push-only coordinator while
  limiting Home Assistant writes to the scheduler, robot, or room scopes that
  changed.
- Bounded in-memory diagnostics report privacy-safe event, queue, discovery,
  evaluation, persistence, snapshot, and entity-write counters and durations.

## Compatibility and migration

Entity IDs, unique IDs, services, controls, settings, Store schema 18, Roborock
adapter schema 11, scheduling behavior, occupancy rules, Party Mode, observe-only
mode, startup settling, checkpointing, and final dispatch revalidation are
unchanged. Running work is not interrupted by a new occupancy transition.

Current room vacancy diagnostics no longer publish live `clear_minutes`, and
backend native states no longer contain elapsed-minute suffixes. They retain
`unoccupied_since`, required minutes, forecast reason, confidence, sample counts,
and allowed/blocking state. External consumers can calculate elapsed time as
`now - unoccupied_since`. Historical decision-audit records retain the captured
`clear_minutes`. The bundled dashboard reconstructs the prior live wording with
one shared timer that pauses while hidden or unused. No Store migration or user
configuration change is required.

## Validation

Tests cover event filtering, dynamic watcher rebinding, capability/topology
refreshes, FIFO transition effects with evaluation coalescing, no-op Store saves,
forced checkpoints, snapshot/entity scopes, stable room vacancy projections,
dashboard elapsed text and timer lifecycle, privacy-safe diagnostics, and the
existing scheduling/recovery/dispatch race suites. Local and GitHub Actions
results are recorded with the published release. Local validation against Python
3.14.7 and Home Assistant 2026.9.2 passed 494 unittest cases and 494 pytest cases
with 95.68% branch-aware coverage. All 31 dashboard tests, Ruff formatting/lint,
strict mypy, root and recursive Python compilation, release contracts, JSON
parsing, and shipped dashboard/icon parity also passed.

## Deployment and acceptance

Install exact tag `v1.16.8` through HACS and validate Home Assistant configuration
before restart. Restart only after both vacuums have positive non-cleaning states.
Do not clear a scheduler hold or dispatch a clean for verification. After restart,
wait for the integration to load and startup settling to finish, verify HACS and
the dashboard resource report `v1.16.8`, confirm robot observations remain
authoritative, and inspect diagnostics/logs for repeated discovery, Store writes,
unrelated entity writes, errors, or blocking-call warnings.

Compare the 20 room Status sensors over a like-for-like 24-hour window with the
12,176-row pre-release baseline. The target is at least an 80% reduction; material
differences in household activity must be explained. Core CPU and RAM remain
regression context only because other integrations share the process.
