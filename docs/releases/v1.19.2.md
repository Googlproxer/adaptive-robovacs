# Adaptive RoboVacs v1.19.2

Released 31 October 2026.

## Changes

- Fix battery learning for Roborock Q10 custom vacuum cleaning. The adapter
  advertises its native `customized` mode so battery validation can compare
  the actual command mode while retaining existing logical forecast profile keys.
- Wait for startup telemetry to confirm the requested fan speed and other
  exposed profile controls before starting a battery sample. Measure elapsed
  time from that confirmed baseline, excluding the unconfirmed startup period.
- Continue rejecting genuine profile changes after sampling begins, invalid
  battery readings, pauses, errors, recharge episodes, inferred completions,
  and jobs crossing a restart.

## Compatibility

Read-only checks on 31 October 2026 confirmed running Core 2026.10.4 matches
the [official stable feed](https://version.home-assistant.io/stable.json).
No Core upgrade is part of this release.

Refresh local and CI test pins to Home Assistant 2026.10.4,
pytest-homeassistant-custom-component 0.13.375, pytest 9.2.0, Ruff 0.17.3,
and mypy 2.4.1. pytest-cov remains 7.1.0. The test plugin still pins pytest
9.0.3, so CI retains the documented two-phase installation with a no-deps
pytest override. Local and CI validation use Python 3.14.9, matching the
running instance's interpreter.
Official checkout v7.0.1 and setup-python v7.1.0 remain on compatible major-v7
pins with read-only workflow permissions.

## Migration and deployment

Store schema remains 20. The optional active-job `battery_started_at` field is
backward compatible. No settings reset, entity ID changes, or historical sample
rewrites are required. Existing battery samples and profile keys are preserved.
Rejected past stages are not backfilled; valid future stages supply new samples.
Roborock adapter capability schema advances to 12 for native mode reporting.

Publish the annotated `v1.19.2` tag and full GitHub Release after validation,
install that exact tag through HACS, validate Home Assistant configuration,
and restart while both vacuums are not cleaning. The dashboard frontend is
unchanged and requires no resource-version update.

## Validation

Local validation on 31 October 2026 passed:

- 588 unittest cases and 588 pytest cases, with 95.19% combined
  statement/branch coverage against Core 2026.10.4 and Python 3.14.9.
- Ruff 0.17.3 formatting and lint, strict mypy 2.4.1 across 63 production
  modules, per-module and recursive Python compilation, and `git diff --check`.
- All 41 dashboard tests, byte-identical dashboard JavaScript copies,
  and root/integration icon parity.

Regression coverage includes Q10 native mode matching for one- and two-pass
custom commands, ordinary single-pass controls, delayed startup fan telemetry,
the confirmed sample's elapsed time and exact forecast profile, profiles that
never match, permanent rejection after mid-clean fan or mode changes, and
baseline persistence with restart-crossed sample rejection.

Windows pytest disables only the Home Assistant plugin (`-p no:homeassistant`)
because its runner imports Linux-only `fcntl`. Linux CI retains the normal
plugin. Tests use synthetic robots and dispatch no real cleaning commands.
