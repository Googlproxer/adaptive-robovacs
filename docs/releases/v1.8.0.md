# Adaptive RoboVacs v1.8.0

Version 1.8.0 prevents a follow-up clean from reaching a Roborock while it is
emptying or washing after the prior stage.

- A discovered same-device Roborock status sensor is now authoritative after
  docking. The scheduler waits through servicing and then observes ten
  uninterrupted seconds of `idle`, `docked`, `charging`, or
  `charging_complete` before dispatching more work.
- A delayed Vacuum then mop occurrence preserves its completed Vacuum stage
  and resumes Mop only after the room is clear and its normal scheduling window
  permits dispatch.
- Command/start failures hold only the affected robot. Mapping and saved room
  profile failures block only their room. Scoped Repairs recheck without
  sending a clean, and unaffected robots and rooms continue scheduling.
- Store schema v10 migrates existing global scheduler faults into their
  registry-keyed robot fault records. No user configuration is changed.

## Validation

Run the full Python unit and compilation checks, plus the dashboard test,
before publishing the release.

## Deployment

Install the `v1.8.0` release through HACS and restart Home Assistant only when
both vacuums are not cleaning. After loading, existing pending occurrences are
preserved; a robot already ready at startup receives a fresh ten-second
confirmation interval before the scheduler can dispatch it.
