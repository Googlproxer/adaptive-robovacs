# Adaptive RoboVacs v1.16.1

Adjacency protection no longer unlocks a scheduled room as soon as a linked
neighbour reports clear. A sensor-equipped neighbour must now pass the same
adaptive vacancy forecast used for the target room.

- The forecast uses the neighbour's persisted occupancy history and the selected
  robot's safe duration for the target stage's exact operation and pass count.
- Low-history fallback retains the existing rounded duration plus 10-minute
  margin. Sufficient comparable successful history may safely permit an earlier
  start under the unchanged confidence rule.
- Occupied and unresolved neighbours still block immediately. Returning
  occupancy resets the clear interval; no-sensor neighbours remain non-blocking.
- Robot-specific resolution, occurrence preparation, the post-checkpoint
  dispatch gate, and every later stage re-evaluate the exact requirement.
- A newly unsafe neighbour abandons an unstarted checkpoint without a fault,
  Repair, or cadence change. Running stages are never interrupted, and explicit
  manual Clean actions retain their override.
- Room Status exposes an optional vacancy diagnostic on clear-but-waiting
  adjacency blockers. Multi-robot previews show each robot's own requirement;
  room-level status is blocked only when no otherwise-compatible candidate can
  pass.

## Compatibility

Public entity IDs, stable unique IDs, adjacency modes, topology rules, and
existing attribute keys are unchanged. Store schema remains 18 because it
already persists `unoccupied_since` and occupancy samples. No migration or new
setting is required.

The test environment is refreshed to Home Assistant 2026.9.2,
pytest-homeassistant-custom-component 0.13.365, and Ruff 0.16.7. The remaining
compatible pins are unchanged.

## Validation

Local validation against Python 3.14.7 and Home Assistant 2026.9.2 passed 458
unittest cases, 458 pytest cases with 96.32% branch-aware coverage, and 30
dashboard tests. Ruff format/lint, strict mypy, root and recursive Python
compilation, and shipped dashboard/icon parity also passed.

Coverage includes the observed 21-second clear interval before the 20.4-minute
Rear Entry stage, restart-restored timestamps, confidence-based early forecasts,
robot-specific durations, later-stage duration changes, preparation and final
dispatch races, manual overrides, active-stage continuation, and diagnostic
attributes. On Windows, pytest explicitly loaded pytest-cov and pytest-asyncio
while other plugin autoload was disabled because Home Assistant 2026.9.2 imports
the Unix-only `fcntl` module during test-plugin startup. Linux GitHub Actions
performs the normal pinned-plugin validation and must pass for this release.

## Deployment

This release stops after repository, tag, GitHub Release, and CI verification.
It does not install through HACS, change dashboard resources, reload the
integration, restart Home Assistant, or dispatch either robot.
