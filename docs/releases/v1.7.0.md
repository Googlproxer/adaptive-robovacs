# Adaptive RoboVacs v1.7.0

## Native direct Custom mopping

- A Roborock now qualifies for direct Custom mopping only when its own
  Home Assistant controls advertise an independent **Custom** cleaning mode,
  a suction **Off** fan option, and independent mop-route and water-intensity
  selectors with concrete options.
- Every qualifying mop stage selects Custom, then its concrete route and water
  intensity, then sets suction Off. All four live states must agree before the
  normal room-clean request is sent. This path never writes **Mop**,
  **Mop-only**, or **Vacuum and mop**, and it does not require an app routine.
- Profile convergence is retried for up to 30 seconds. Missing, non-concrete,
  or unconfirmed direct controls record `skipped_no_mop` and leave the
  scheduler running without a Repair or room-clean request.
- Ordered programs remain physical stages: **Vacuum then mop** credits the
  completed vacuum before it prepares Custom mopping; **Mop then vacuum**
  starts vacuum only after its mop stage physically completes.

## Migration and dashboard

- Store schema v9 adds a registry-keyed, one-time migration for a qualifying
  robot's own defaults. Any non-concrete route becomes **Standard** and any
  non-concrete water value becomes **Medium**. A later user change is not
  overwritten. Room overrides are intentionally not migrated because another
  vacuum may use them.
- The vacuum dashboard shows the direct mopping contract, plus direct Custom
  mop-route and water-intensity labels.

## Validation and deployment

- Run the complete unit, compilation, dashboard syntax, and dashboard-copy
  parity checks before HACS installation.
- No live Rob clean or mode-change test is part of this release. Install the
  exact tag through HACS only after both vacuums are idle, then restart Home
  Assistant and verify the integration loads.
