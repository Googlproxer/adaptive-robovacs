# Adaptive RoboVacs v1.13.0

Release date: 2026-09-06.

## User-visible changes

- Preserves all existing entity identities, services, response fields, dynamic
  entities, dashboards, scheduling rules, learned history, and restart
  recovery.
- Corrects dashboard manual-clean readiness so a physically docked compatible
  robot may be selected even when scheduled-readiness policy would reject it.
- Requires Home Assistant 2026.9 or newer.

## Architecture

- Replaces the monolithic coordinator with a serialized application command
  queue, pure planner and job reducers, typed discovery/observation/gateway
  boundaries, independent infrastructure services, immutable presentation
  snapshots, and a push-only `DataUpdateCoordinator`.
- Stores config-entry runtime objects exclusively in typed `entry.runtime_data`.
- Splits map recovery into typed models, validated Store codec, service, and
  existing-Roborock-runtime bridge components.
- Adds AST dependency tests, strict mypy, Ruff, pinned Python 3.14 tooling, and
  behavioral migration/dispatch/recovery tests.

## Migration and safety

- Scheduler storage advances from internal schema 15 to 16 while retaining the
  existing Store key and envelope version.
- All legacy schemas are fully validated before the first v16 write. Migration
  is idempotent.
- Stable entity-registry IDs are the durable robot identity. Unresolved legacy
  keys are retained, blocked from dispatch, and surfaced through Repairs.
- Malformed or newer storage starts in storage-safe observe-only mode and is
  never overwritten.
- Checkpoint-before-dispatch, fresh stage revalidation, observed robot
  authority, scoped safe failures, and no automatic retry after uncertainty are
  preserved.

See [architecture](../architecture.md) and
[migration guide](../migration-v1.13.0.md).

## Deployment

Install the exact `v1.13.0` release through HACS and restart Home Assistant.
The existing scheduler Store is migrated in place to schema 16 after complete
validation; malformed or newer data remains untouched in storage-safe mode.
