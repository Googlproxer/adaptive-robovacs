# Adaptive RoboVacs v1.3.0

## User-visible changes

- Added an integration-owned vacuum adapter schema with a portable generic
  fallback for vacuums without a vendor adapter.
- Added the first enhanced adapter for compatible Roborock vacuums. Two-pass
  room work uses one native cross-hatched command after resolving the current
  Home Assistant area mapping.
- Added **Cleaning passes** to every room card: Robot default, 1 pass, or
  2 passes. Explicit two-pass requests are never emulated or downgraded.
- Added live adapter and pass capability diagnostics to each vacuum status.
- Added a durable scheduler-wide start-failure halt, translated Home Assistant
  Repairs issues, affected target-card status, and a confirmed non-dispatching
  **Recheck and resume** action.
- Added robot fan-speed selection where the vacuum advertises choices.

## Upgrade notes

No existing entity or unique ID is removed. Existing rooms migrate to **Robot
default**, preserving their prior robot-wide double-pass behavior. Unknown
vacuum vendors continue to use standard Home Assistant area cleaning.

After updating through HACS and restarting Home Assistant, review each room's
new Cleaning passes control. Keep Home Assistant's vacuum-segment area mapping
current; Adaptive RoboVacs does not maintain a second mapping.

If a scheduler start fails, new scheduler work stays halted across all vacuums
until the Home Assistant Repair flow or confirmed dashboard action completes a
successful non-dispatching recheck. Dismissing the Repair is not a resume.
