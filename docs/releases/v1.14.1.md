# Adaptive RoboVacs 1.14.1

## Changes

- Move the scheduler application into `application/`, with `core.py` owning
  state and composing the focused actions, dispatch, evaluation, events,
  faults, jobs, legacy-map, policy, recovery, room-recovery, settings, and
  water-confirmation modules.
- Preserve `from .application import SchedulerApplication` through a small
  package initializer. Component filenames no longer repeat `application_`.
- Preserve the exact mixin order and shared clock/timer behavior. Internal
  helper imports remain deferred to avoid circular imports during startup.
- Update test patch targets, resolve nested imports in architecture checks,
  and cover fresh-process package imports and the public class identity.
- Document recursive compilation so local validation covers nested packages.

This patch changes source organization only. Scheduling decisions, command
ordering, dispatch safeguards, observed robot authority, public entity IDs,
and durable scheduler data are preserved. Per-module logger names follow the
new paths, such as `custom_components.adaptive_robovacs.application.recovery`;
integration-level logger configuration continues to cover these modules.

## Migration

No additional migration is required from v1.14.0. Store schema 17, its
storage key/envelope, public services, entity IDs, unique IDs, and dashboard
JavaScript are unchanged by this patch.

Upgrades from versions before v1.14.0 also include its room recovery and
feature removals. See the [v1.14.0 migration guide](../migration-v1.14.0.md).

## Validation

The pre-refactor baseline passed 412 Python tests and 350 subtests with
96.10% coverage, plus 25 dashboard tests, Ruff formatting/lint, strict mypy,
unittest compatibility, and both root-module and recursive compilation.

Dependency and CI pins were rechecked on 8 September 2026 against official
[PyPI package metadata](https://pypi.org/project/homeassistant/),
[checkout releases](https://github.com/actions/checkout/releases), and
[setup-python releases](https://github.com/actions/setup-python/releases).
The existing pins remain current: Home Assistant 2026.9.1, its test plugin
0.13.364, pytest 9.1.1, pytest-cov 7.1.0, Ruff 0.16.6, mypy 2.3.1, and the
v7 majors of both official actions. CI and local validation use Python 3.14.7.
A read-only Home Assistant check confirmed Core 2026.9.1; no Core update is
part of this release.

The documented pytest 9.1.1/test-plugin dependency exception from v1.14.0 is
retained. Windows validation disables pytest plugin autoload and explicitly
loads `pytest_asyncio.plugin` and `pytest_cov.plugin`; Ubuntu CI uses normal
plugin loading.

Final local validation:

- Pytest: 416 tests and 360 subtests passed; coverage 96.11% (95% required).
- Unittest compatibility: 416 tests passed.
- Dashboard tests: 25 passed.
- Ruff formatting/lint and strict mypy: passed.
- Root-module compilation and recursive integration compilation: passed.
- Dashboard JavaScript and brand icon byte-parity checks: passed.
- All thirteen moved modules retain identical non-import syntax trees after
  normalizing the renamed core-module alias and the updated documentation
  reference. The class inheritance order is unchanged.

The existing five third-party deprecation warnings remain; the refactor adds
no new warnings. GitHub Actions must pass for the released commit before HACS
installation.

## Deployment

Publish an annotated `v1.14.1` tag and full GitHub Release, verify CI succeeds,
then install that exact tag through HACS and validate Home Assistant's
configuration.

This deployment is explicitly **code installation only**: do not restart
Home Assistant or reload the integration. The existing v1.14.0 application
remains loaded; the new package activates at a later user-initiated restart.
HACS's installed version confirms downloaded code, not activation of the new
Python modules. Post-restart runtime verification is deferred accordingly.
