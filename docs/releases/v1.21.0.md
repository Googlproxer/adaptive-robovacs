# Adaptive RoboVacs v1.21.0

Release date: 2026-11-06.

## Changes

- Preserve human-vacancy timers when short radar/motion episodes align with
  observed robot movements. Resolve numeric native locations through Home
  Assistant registry mappings; never compare native room names.
- Handle delayed room reports and unavoidable intermediate transit rooms in
  the saved floor plan. Keep pending classification, established human presence,
  stale or ambiguous evidence and persistent post-departure occupancy blocking.
- Defer vacancy learning until attribution settles. Robot episodes add no false
  vacancy samples; mixed/uncertain episodes are censored. All scheduling layers
  consume the same effective occupancy and clear-time anchor.
- Keep raw occupancy entity behavior and stable IDs, with added attribution
  diagnostics and room-card explanations. Independently recheck physical traffic
  immediately before an automatic start.
- Add schema 22 checkpoints and a one-time reset of unclassified vacancy samples
  only for rooms gaining supported attribution. Preserve cadence, cleaning
  history, duration/battery models and restart-safe jobs.
- Use passive cached native observations, bounded recent visits, cached transit
  inference and deadline-driven wakeups. Unchanged location heartbeats do not
  trigger planning, storage or entity publication. Retain v1.20.3 persistence
  caches, atomic writes and write/cancellation recovery contracts.

## Compatibility and migration

Requires Core 2026.11.0. The read-only implementation check found that version
running and in the official stable feed; existing compatible CI/dependency pins
remain unchanged. See the [migration guide](../migration-v1.21.0.md), including
the accepted human-presence tradeoff and backup/rollback requirements.

## Validation

Local validation passed 689 pytest tests with 95.51% combined branch/line
coverage, 689 unittest tests, Ruff formatting/lint, strict mypy, top-level and
recursive compilation, 45 dashboard unit tests and ten browser regressions
(two desktop touch tests intentionally skipped). Dashboard and icon copies are
byte-identical, and the pinned environment passes dependency compatibility checks.

The matched 100-sample v1.20.3 cleaning comparison passes budgets and regression
checks. Location heartbeat p95 is 0.048 ms, with zero added evaluations, saves or
publications. Offline backend and dashboard invariants pass; the largest backend
case retains documented advisory budget overruns. See the
[performance documentation](../performance.md) for measurements and scope.
Live device acceptance remains part of a later approved deployment.

## Deployment

Publish an annotated version tag and full GitHub Release only after validation,
then require successful CI before installing the exact tag through HACS. Validate
configuration and confirm both robots are idle before restarting Home Assistant.
Verify supported numeric locations, raw/effective occupancy, timer continuity and
human occupancy before/after a robot visit. Do not use a live test clean as a
substitute for explicit deployment authorization.
