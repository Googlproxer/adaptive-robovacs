# Adaptive RoboVacs v1.16.2

Vacuum-then-mop occurrences can no longer retain a completed vacuum indefinitely
while their mop stage remains pending. The prerequisite vacuum is now fresh for
12 hours; at the boundary, the same occurrence returns to vacuum before mopping
can start.

- Scheduled and dashboard-manual vacuum-then-mop occurrences use the guard.
- A completion timestamp that is missing cannot prove freshness and requires a
  repeat vacuum.
- The rewind retains the occurrence ID, due time, robot assignment, adapter
  contract, stage pass counts and profiles, source, and manual metadata.
- Old stage attempt timestamps and water authorization are cleared. The current
  vacuum stage exposes `mop_delay_expired` through the existing reason field.
- State is normalized after job reconciliation and checked again before
  preparation and final dispatch. Crossing the boundary during a transaction
  persists the rewind, abandons the stale mop candidate without a fault or
  cadence change, and queues a fresh evaluation.
- Explicit mop-only and mop-then-vacuum programs, external cleans, active mops,
  cadence and duration history, faults, Repairs, occupancy/adjacency policy, and
  observed robot authority are unchanged.

## Compatibility

Store schema remains 18. Public entity IDs and stable unique IDs are unchanged,
and there is no new Home Assistant setting or dashboard control. The policy is
fixed at 12 hours for this release. No dashboard JavaScript or resource
cache-bust is required.

The pinned acceptance environment remains Home Assistant 2026.9.2,
pytest-homeassistant-custom-component 0.13.365, pytest 9.1.1, pytest-cov 7.1.0,
Ruff 0.16.7, and mypy 2.3.1. These and the official checkout/setup action
majors were rechecked immediately before release; no compatible stable pin
change was required.

## Validation

Local validation against Python 3.14.7 and Home Assistant 2026.9.2 passed 464
unittest cases and 464 pytest cases with 96.28% branch-aware coverage. The 30
dashboard tests, Ruff format/lint, strict mypy, root and recursive Python
compilation, release contracts, and shipped dashboard/icon parity also passed.
GitHub Actions must reproduce the validation before deployment.

Focused coverage includes the days-old production shape, the 11:59:59 and exact
12-hour boundaries, missing completion timestamps, Store restoration, repeated
normalization, scheduled and dashboard-manual sources, preserved profiles and
metadata, excluded programs and running stages, stale water approval cleanup,
and expiry during final dispatch revalidation.

## Deployment

Install the exact `v1.16.2` HACS release and validate Home Assistant
configuration. Restart only after both vacuums are observed neither cleaning nor
servicing. After restart, verify the integration is loaded, HACS reports
`v1.16.2`, robot observations remain authoritative, and no new faults appear.
Do not manufacture or dispatch a clean solely for verification.
