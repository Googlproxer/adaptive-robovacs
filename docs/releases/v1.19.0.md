# Adaptive RoboVacs v1.19.0

Released 22 October 2026.

## Changes

- Build managed multi-room queues from due, compatible, clear rooms. Preserve
  never-cleaned/oldest-cleaned priority, moving a room earlier when that makes
  its clear window fit. Complete each room's saved program before the next room.
- Check vacancy through each room's actual expected completion, including queue
  delays and dock/preparation allowances. Revalidate after awaited preparation
  and checkpoint writes, immediately before starting each physical stage.
- Learn battery use from valid observed stages. Require three samples for each
  robot/stage profile; retain single-room behavior during learning. Budget the
  complete run using conservative durations, an 80th-percentile discharge rate
  with a 25% margin, and an inclusive 20% finishing reserve.
- Apply minimum-start battery once per managed run. Use actual charge for later
  stages and trim pending rooms when necessary; future charging is never counted.
  Explain programs that cannot fit even at full charge without changing passes.
- Remove blocked pending rooms and leave them due. Let the observed current room
  finish both stages despite its own occupancy changes, retaining all other gates.
- Persist reservations, progress, and learning through restart. Keep physical jobs
  single-room, preserve uncertain-start holds, and recognize recharge/resume as
  unfinished work rather than dock completion.
- Show queue order, remaining duration, estimated finish, battery estimates, and
  learning progress. Queued rooms remain distinct from actively cleaning rooms.

See the [migration guide](../migration-v1.19.0.md).

## Compatibility

Read-only checks on 22 October 2026 confirmed the running Core and available
stable update are both 2026.10.2, consistent with the
[official stable feed](https://version.home-assistant.io/stable.json).
Local and CI pins use Core 2026.10.2 and
[pytest-homeassistant-custom-component](https://pypi.org/project/pytest-homeassistant-custom-component/)
0.13.373. Python is 3.14.8 and Ruff is 0.17.1; pytest 9.1.1 retains the documented
no-deps override of the plugin's pytest 9.0.3 pin. pytest-cov 7.1.0 and mypy 2.4.0
remain current compatible pins. No live Core upgrade is required.
The official checkout v7.0.1 and setup-python v7.0.0 releases retain the existing
compatible major-v7 action pins and read-only workflow permissions.

## Validation

Local validation on 22 October 2026 passed:

- 580 pytest cases and 95.16% combined statement/branch coverage;
  the same 580 unittest cases passed against Core 2026.10.2.
- Ruff format/lint and strict mypy across 63 production modules; per-module
  Python compilation and recursive compilation.
- 41 dashboard tests and JavaScript syntax checks; byte-identical shipped and
  standalone dashboard sources and HACS/integration icons.
- 10 browser cases across desktop Chromium, Android Chromium, and mobile WebKit.
  The two touch-swipe platform skips are intentional: native swipe input is
  exercised in the Android project.

Coverage includes actual queue-to-dispatch transactions, cumulative vacancy and
DST boundaries, per-profile battery learning and invalidation, queue shrinking,
current-room continuation, uncertain starts, restart recovery, prerequisite
expiry, recharge/resume, migration, and queued-room presentation.

Windows async tests use local event-loop socket access and synthetic robots;
no real cleaning command was dispatched. The Linux CI run also validates the
Home Assistant test plugin with its native platform dependencies.

## Deployment

Install the exact `v1.19.0` release through HACS, validate Home Assistant's
configuration, and restart only while both robots are docked and error-free.
Refresh the dashboard resource to `?v=1.19.0`. Check that the integration is
loaded, startup settling has finished, and the existing robot, room, and
recovery state is intact. Battery learning starts empty, so initial scheduled
cleans remain single-room until the required profile samples are available.
