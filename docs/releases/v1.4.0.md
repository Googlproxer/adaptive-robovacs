# Adaptive RoboVacs v1.4.0

Version 1.4 introduces water-aware ordered cleaning programs.

## Highlights

- Vacuum only, Mop only, Vacuum then mop, and Mop then vacuum programs, with a
  robot default and optional per-room override.
- One cadence per room and a durable multi-stage occurrence that never replays
  a completed stage after restart.
- Fresh occupancy, time-window, battery, profile, mapping, and water checks
  before every physical stage.
- Independent vacuum and mop pass defaults/overrides, including native
  Roborock two-pass cross-hatching for either stage when supported.
- Authoritative Roborock water readiness from the same-device Mop attached,
  Water box attached, and Water shortage entities.
- Fail-closed, one-hour **Confirm water** / **Cancel mopping** notifications for
  mop-capable robots without water telemetry, sent to all current Companion
  app targets.
- Throttled all-user no-water notifications and a Home Assistant Repair when no
  required notification can be delivered.

## Migration

- The old vacuum cadence becomes the single cleaning cadence. The old mop
  cadence entity is retired.
- The most recent successful vacuum or mop timestamp seeds the new cadence
  anchor, preventing an immediate duplicate clean after upgrade.
- The existing room pass selector keeps its entity ID and becomes Vacuum
  passes. Mop passes is new and defaults to one pass.
- The robot Mopping enabled control is replaced by Cleaning program. An enabled
  mop-capable robot migrates to Vacuum then mop; disabled migrates to Vacuum
  only.
- Existing dashboard cards discover the new controls automatically. Review
  each robot and room program before leaving observe-only mode.

## Safety and deployment

No-water and unconfirmed-water outcomes skip only the mop stage. They never
halt vacuuming. An actual profile, command, or start-confirmation failure still
engages the durable system-wide scheduler halt and requires the Repair recheck.

Install `v1.4.0` through HACS and restart Home Assistant. The migration is
restart-safe and does not persist native Roborock targets, water entity IDs,
mobile target names, or notification action tokens.
