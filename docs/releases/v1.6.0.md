# Adaptive RoboVacs v1.6.0

Version 1.6.0 adds native two-pass room cleaning for compatible Roborock
Q10/B01 vacuums.

- Q10 vacuums use their custom-clean protocol rather than the legacy
  `app_segment_clean` command that those vacuums reject.
- A two-pass vacuum clean configures the transient Q10 profile, selects
  **customized** mode, and issues one native room-clean start with clean count
  two. It never approximates two passes by starting the room twice.
- The Q10 path is limited to vacuum-only two-pass work. Mopping remains on its
  existing supported paths.
- `max_plus` is intentionally unsupported for Q10 custom cleaning. The
  scheduler rejects that profile safely rather than lowering the selected fan
  speed.
- Native map targets and custom payloads remain transient; they are not stored,
  logged, or surfaced on cards or Repairs.
- Existing portable and legacy Roborock behavior is unchanged. No Store or
  entity migration is required.

## Validation

The release candidate passed 139 Python unit tests, Python compilation checks,
11 dashboard Node tests, dashboard-copy byte parity, HACS icon byte parity,
and the repository release-contract checks.

## Deployment notes

Install the exact `v1.6.0` tag through HACS and restart Home Assistant only
while both vacuums are idle. Before enabling a Q10 two-pass room, select a
supported fan speed (`quiet`, `balanced`, `turbo`, or `max`). Verify the first
run in an unoccupied mapped room and confirm that the vacuum reports normal
cleaning and completion state transitions.
