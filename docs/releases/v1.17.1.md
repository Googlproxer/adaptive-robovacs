# Adaptive RoboVacs v1.17.1

## Fix

The scheduler now captures each native cleaning-time reading from its Home
Assistant state-change event. After a managed job has an observed cleaning start
and a timer baseline, the first reading above that baseline sets a durable
`native_timer_progress_seen` flag. Later timer ticks do not cause additional
Store writes. The flag survives pauses, errors, and integration restarts.

A final zero timer delta still creates a dispatch fault when no progress was
observed. If the timer advanced and later reset, the zero delta no longer
creates that fault. Existing interrupted-job and duration-learning rules
remain in effect. The fault log includes the timer baseline, final delta, and
progress evidence.

Older active-job checkpoints default the new optional field to false. The
Store schema and public entity IDs are unchanged. This release does not
retroactively credit the interrupted Bedroom 1 clean from 26 September.

pause, robot error, resume, and docking; persistence across restart; a single
extra Store write; and the true zero, missing, invalid, and native-app cases.
