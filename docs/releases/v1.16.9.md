# Adaptive RoboVacs v1.16.9

This focused acceptance fix completes the v1.16.8 entity-scope optimization.
Live post-deployment diagnostics showed that rooms inside an active desired
cleaning window still changed their projected `desired_window_start` on every
evaluation. That clock-only value caused Home Assistant to rewrite every entity
in those room scopes even though no scheduling or safety input had changed.

Room snapshot equality now ignores four presentation-only values that advance
with the clock: `last_cleaned_display`, `desired_window_start`, `next_clean_at`,
and `next_clean_window_end_at`. The coordinator still publishes the newest full
immutable snapshot, but room entities are notified only when a meaningful room
dependency changes. The next meaningful update carries the current presentation
values.

Occupancy state and timestamps, adjacency decisions, block reasons, robot
eligibility, schedules, active jobs, faults, Repairs, profiles, and all safety
inputs remain equality-significant. Immediate occupancy blocking, Party Mode,
observe-only mode, startup settling, checkpoint-before-dispatch, final fresh
pre-dispatch validation, and the rule that running work is not interrupted are
unchanged.

There is no Store schema migration and no public entity, unique ID, service,
control, or setting change. Upgrade from v1.16.8 through HACS and restart only
after both vacuums have positive non-cleaning states. Do not clear scheduler
holds or dispatch a verification clean.

Validation includes a regression proving that clock-only room projection changes
produce an empty room delta while an occupancy change still targets the affected
room. The complete unit, dashboard, lint, type, compilation, coverage, release,
and parity checks are required before publication.
