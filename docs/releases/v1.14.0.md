# Adaptive RoboVacs 1.14.0 — draft

## Changes

- Add persistent room Repairs for robot errors during integration-owned,
  single-room scheduled and dashboard cleaning occurrences.
- After ten continuous seconds of docked, terminal-ready observations with no
  current error, detach the interrupted job and release its matching robot
  hold. The affected room remains blocked while other eligible rooms can clean.
- Repair confirmation permits only the unfinished stage to retry through
  normal scheduling. It preserves completed stages, passes, profiles, and robot
  assignment, clears manual bypasses, and sends no physical commands. Stale
  confirmations cannot clear newer episodes, and other faults remain intact.
- Preserve physical resume before detachment and confirmed completion, without
  treating an unresolved error's return to dock or elapsed time as success.
- Discover normalized robot-error evidence through adapter registry metadata,
  with safe descriptions and conservative handling of unavailable or ambiguous
  configured diagnostics.
- Advance the scheduler payload to schema 17 and reconstruct matching legacy
  error holds using fresh observations. Ambiguous jobs retain their robot hold
  and receive an explicit robot Repair.
- Update the Home Assistant requirement and test pin to 2026.9.1, its test
  plugin to 0.13.364, and the CI Python pin to 3.14.7.
- Remove bedroom-transit scheduling rules: the all-bedrooms occupancy gate,
  separate daytime window, and special unresolved-occupancy exclusion.
- Remove transit time selectors, configuration/global settings, and the
  `bedroom_transit` room schedule attribute.
- Clean obsolete settings from existing config entries and valid scheduler
  state, and retire only the owning entry's obsolete select registry records.
- Update current setup, architecture, and future feature plans to use room-local
  occupancy without carrying forward the removed feature.
- Remove the complete map snapshot/recovery feature: manual and post-clean
  captures, archives, preview selectors/cameras, capture-status sensors, and
  retained-map activation/confirmation services and dashboard controls.
- Delete only entry-owned obsolete map entities and archives automatically on
  upgrade, including renamed entities and corrupt archives. Preserve robot maps,
  recorder history, floor plans, and all other scheduler state.
- Keep old map-selection holds blocked until an explicit compatibility Repair
  validates Home Assistant room mapping and saves the scoped release. The robot
  must be docked/idle with no active job; confirmation sends no physical command.

Ordinary bedroom classification, saved room settings, manual-clean behavior,
Party Mode, observe-only mode, startup settling, and robot readiness rules remain.
Room adjacency is separate future work.

## Migration

This release removes public controls and attributes. See
[the migration guide](../migration-v1.14.0.md) for removed identifiers, consumer
cleanup, the validated schema-16-to-17 migration, and recovery confirmation.
Deleting the obsolete HA label also removes its assignments and can change
scheduling in an older installed version.

## Validation and deployment

Toolchain pins checked against current stable releases on 7 September 2026:

- Python 3.14.7 and Home Assistant 2026.9.1.
- pytest-homeassistant-custom-component 0.13.364 and pytest 9.1.1.
- pytest-cov 7.1.0, Ruff 0.16.6, and mypy 2.3.1.
- `actions/checkout@v7` and `actions/setup-python@v7` remain current compatible
  action majors.

Home Assistant and test-package versions were verified against their PyPI
metadata; Python was verified against the
[3.14.7 release](https://www.python.org/downloads/release/python-3147/).

Local validation on Windows with Python 3.14.7 and Home Assistant 2026.9.1:

- Pytest: 412 tests and 350 subtests passed; total coverage 96.10% (95% required).
- Unittest compatibility: 412 tests passed.
- Dashboard tests: 25 passed.
- Ruff formatting/lint and strict mypy: passed.
- Top-level module compilation and recursive integration compilation: passed.
- Dashboard JavaScript and brand icon byte-parity checks: passed.

The test plugin still declares pytest 9.0.3. The documented two-phase install
retains pytest 9.1.1; `pip check` reports only that known dependency exception.
Windows pytest validation disables plugin autoload and explicitly loads
`pytest_asyncio.plugin` and `pytest_cov.plugin`, because the Home Assistant
plugin imports the Linux-only `fcntl` module. All tests, including Home
Assistant integration tests, run with this configuration. Ubuntu CI retains
normal plugin loading.

These results cover all three 1.14.0 changes: room recovery, bedroom-transit
removal, and map snapshot removal. The reduced test count reflects deletion of
feature-specific tests; new regressions cover upgrade cleanup, Store migration,
legacy hold confirmation, save failures, and retained dashboard controls.
Validation uses real Home Assistant lifecycle, Store, Repair, and scheduler
boundaries without operating live vacuums. A read-only check confirmed installed
Core 2026.9.1 matches the available stable update and the test pin.

## Draft release and deployment

The final change is committed to `main`, with an annotated `v1.14.0` tag and a
GitHub **draft** release prepared only after the final commit's CI passes.
The draft remains unpublished. Publishing it is a separate action.

**Not deployed to Home Assistant.** No HACS installation, Home Assistant
configuration change, integration reload, or restart is part of this release
preparation. Before a later deployment, audit consumers of the removed services
and controls, then follow the approved exact-tag HACS and safe-restart procedure.
