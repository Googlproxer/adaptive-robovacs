# Adaptive RoboVacs v1.18.1

Floor-plan cards previously rebuilt their entire Home Assistant card and SVG on
every state update, including unrelated updates. This could reset page scrolling
when an asynchronous card wrapper briefly lost its height. The SVG also disabled
all browser touch gestures in view mode, limiting touch scrolling to the header.

## Changes

- Retain the card, SVG, room and sensor nodes. Reconcile displayed changes by
  stable IDs, preserving page scrolling, sensor focus and pointer capture.
- Filter updates to the selected floor's displayed data and batch them through
  the shared animation-frame queue. Same-revision occupancy and friendly-name
  updates remain live in view mode; hidden views defer work and disconnected
  cards clean up.
- Allow browser scrolling and pinch zoom across the diagram in view mode. Edit
  mode reserves gestures only on draggable targets; blank canvas still scrolls.
- Capture every drag's active pointer, ignore additional pointers, keep its
  coordinate scale fixed, and restore starting geometry on pointer cancellation,
  lost capture or disconnection. Connections are removed on a tap/click rather
  than the start of a possible swipe.
- Retain atomic saves and their original revision. Failed saves preserve drafts;
  floor/entry changes and revoked admin access discard editing safely.

See the [migration guide](../migration-v1.18.1.md). Store schema remains 19;
public entity IDs, saved floor geometry and all scheduling policies are unchanged.

## Compatibility

The running Core and available stable version were checked read-only on
13 October 2026: both are 2026.10.1, as listed by the
[official stable feed](https://version.home-assistant.io/stable.json).
Local and CI tests now use Core 2026.10.1 with
[pytest-homeassistant-custom-component](https://pypi.org/project/pytest-homeassistant-custom-component/)
0.13.372, which pins that Core version. No live Core upgrade is required.

Python remains 3.14.7, pytest 9.1.1 (the documented no-deps override of the
plugin's 9.0.3 pin), pytest-cov 7.1.0, Ruff 0.17.0 and mypy 2.4.0.
The verified official [checkout](https://github.com/actions/checkout/releases/tag/v7.0.1)
and [setup-python](https://github.com/actions/setup-python/releases/tag/v7.0.0)
actions retain compatible major v7 and `contents: read` permissions.
Browser tests pin Playwright 1.64.0 and cover desktop Chromium, Android Chromium
and mobile WebKit using synthetic data and an asynchronous slotted card wrapper.

## Validation

Local validation on 13 October 2026 passed:

- 548 pytest cases with 95.16% combined statement/branch coverage, plus 548
  unittest cases against the updated compatible Core/plugin pair.
- Ruff format/lint, strict mypy across 60 production modules, per-module Python
  compilation and recursive compilation.
- 40 Node dashboard tests, JavaScript syntax, release metadata and byte-identical
  dashboard JavaScript/icon copies.
- 116 browser assertions at desktop and 390-pixel phone widths, including
  scrolling during/after live updates, retained DOM/focus, all drag types,
  cancellation/lost capture/disconnection, links, palette, saves and recovery.
- A real browser room drag retained the SVG and released capture successfully.

The CI browser suite additionally checks Chromium, Android Chromium touch swipes,
mobile WebKit and orientation changes. Native touch-swipe input is tested on
Android Chromium; WebKit checks DOM, gesture policy, dragging and responsive
layout. Physical iOS Companion-app validation remains a device check.

Windows pytest disables plugin autoload and explicitly loads
`pytest_asyncio.plugin` and `pytest_cov.plugin`, avoiding the HA plugin's Unix-only
`fcntl` import. Tests run with normal local event-loop socket access and isolated
mock robots; no live robot is dispatched.

## Deployment

Install exact tag `v1.18.1` through HACS after CI succeeds, validate Home Assistant
configuration and restart with both vacuums docked and error-free. Verify the
integration is loaded, HACS shows v1.18.1 and the existing frontend module URL
uses `?v=1.18.1`. Reload the dashboard and inspect both stacked floor plans.
No test clean, fault clearance or scheduling-setting change is required.
