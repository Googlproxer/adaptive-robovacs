# Adaptive RoboVacs v1.7.1

## Stable native Roborock mop-only preparation

- Roborock route, water-intensity, cleaning-mode, and fan controls are linked
  by the native integration. Concrete route and water settings can therefore
  report a transient combined cleaning mode even though Adaptive RoboVacs did
  not select it.
- Each Rob mop stage now sets its concrete route and water intensity first,
  then selects native **Mop** and suction **Off** as the final controls. The
  room-clean request is sent only after the live states confirm Mop, Off, the
  requested route, and a non-off water intensity.
- The integration never writes **Custom** or **Vacuum and mop** on this path.
  An unconfirmed profile, unavailable control, or profile-write error records
  `skipped_no_mop`; it does not trigger a Repair or a scheduler-wide halt.
- The bounded 30-second profile deadline includes Home Assistant service-call
  latency, so it returns the safe mop-only outcome before the general dispatch
  watchdog can interfere.

## Programs, settings, and dashboard

- Manual mopping, scheduled mopping, **Vacuum then mop**, and **Mop then
  vacuum** all use the same native mop-only contract. A completed preceding
  vacuum stage remains credited if the later mop stage is skipped.
- Existing robot route and water defaults—and the one-time schema-v9 migration
  marker—are retained. No room overrides or public entity IDs are rewritten.
- Rob status and dashboard text now say **Mop mode with suction off**.

- Run the complete unit suite, Python compilation, dashboard syntax checks,

- Install the exact `v1.7.1` tag through HACS only when both vacuums are idle,

- This release authorizes one post-deployment manual, mop-only Brewery pass.
  Confirm the final native profile and room-clean dispatch observation; do not
