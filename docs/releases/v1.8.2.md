# Adaptive RoboVacs v1.8.2

Version 1.8.2 prevents a room clean that the vacuum reports as zero minutes
from being credited as successful.

- The zero-duration check applies only to room cleans initiated through
  Adaptive RoboVacs: scheduled cleans, dashboard manual cleans, and
  Home Assistant robot-control room cleans. Native-app activity remains
  untracked and is never attributed to a scheduled room.
- A zero or negative duration from the discovered native cleaning-time sensor
  fails the active clean before cadence or duration learning is updated. Its
  pending stage remains due and the affected robot receives a persistent
  Repair hold; unaffected robots remain schedulable.
- The check also applies when a restart recovers a persisted native timer
  baseline, keeping the failure behaviour restart-safe.

## Validation

- `python -m unittest discover -s tests -v`
- `python -m py_compile custom_components/adaptive_robovacs/*.py`
- `node --test tests/test_dashboard.mjs`

## Deployment

Install the exact `v1.8.2` GitHub Release through HACS. Confirm both vacuums
are not cleaning or servicing before restarting Home Assistant. A zero-minute
result will create a robot-scoped Repair; restore the vacuum's native map, then
submit the Repair while that vacuum is docked to resume its scheduler work.
