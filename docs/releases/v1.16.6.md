# Adaptive RoboVacs v1.16.6

This release fixes Roborock profile application when one native control resets
another shortly after Home Assistant reports a successful service call. In the
reported Rumpus clean, Adaptive RoboVacs requested maximum suction and then set
the operation to Vacuum. The later linked update reset Rob's fan speed to
Balanced before the clean began. The same native behaviour could reset mop
water intensity while switching into Mop mode.

- Vacuum profile application now selects the requested operation first, waits
  for Roborock's linked state update to settle, and writes fan speed last.
- Adaptive RoboVacs confirms the combined operation and fan-speed state after a
  second settling interval. It retries the complete transaction within a
  bounded 20-second deadline and blocks the room dispatch if the requested
  tuple cannot be observed.
- Native mop application now lets route and operation changes settle before it
  writes water intensity and suction. It then confirms route, operation, water
  intensity, and suction together within the existing bounded preparation
  window.
- A failed confirmation remains a safe profile-application fault: no area-clean
  command is sent, no room completion is credited, and the next eligible
  evaluation may retry normally.
- Q10 custom-clean transport and generic portable controls are unchanged.

## Compatibility

Public entity IDs, stable unique IDs, dashboard resources, Store schema 18,
room cadence, manual override scope, and saved profile values are unchanged.
The Roborock adapter schema advances from 10 to 11 to identify the changed
profile-application contract. This is an integration runtime change, so an
exact-tag HACS installation and Home Assistant restart are required.

The running stable environment is Home Assistant Core 2026.9.2. Its update
entity reported no newer stable Core release on 16 September 2026. The pinned
acceptance environment remains Home Assistant 2026.9.2,
pytest-homeassistant-custom-component 0.13.365, pytest 9.1.1, pytest-cov 7.1.0,
Ruff 0.16.7, and mypy 2.3.1. PyPI reported those pins current, and the official
`actions/checkout@v7` and `actions/setup-python@v7` majors remain current.

## Validation

Focused adapter coverage reproduces the delayed fan reset observed after a
Vacuum-mode write and verifies that maximum suction is applied last and remains
confirmed. It also reproduces delayed route and mode resets during mop setup,
verifies the final water intensity and suction, and proves that a fan speed
which never remains stable blocks before any clean dispatch.

Local validation against Python 3.14.7 and Home Assistant 2026.9.2 passed 481
unittest cases and 481 pytest cases with 95.84% branch-aware coverage. The 30
dashboard tests, Ruff formatting/lint, strict mypy, root and recursive Python
compilation, release contracts, JSON parsing, and shipped dashboard/icon parity
also passed. GitHub Actions must reproduce the release validation before live
deployment.

## Deployment

Install exact tag `v1.16.6` through HACS and validate Home Assistant
configuration before restart. An active-clean restart is permitted only with
explicit user authorization; otherwise wait for positive docked, non-servicing
states. After restart, wait for the integration to report loaded and for startup
settling to finish, verify HACS reports `v1.16.6`, and confirm active robot state
was recovered from observation. Do not dispatch a clean solely for verification.
