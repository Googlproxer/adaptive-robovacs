# Adaptive RoboVacs v1.18.0

Rooms with extensive short vacancy history could remain forecast-blocked even
after a long uninterrupted clear period. This release conditions the forecast
on the elapsed vacancy and retains a configurable, separately labelled fallback.
It also makes the exact decision and the reasons for missed windows visible.

## Changes

- Estimate remaining vacancy from surviving historical samples; require six
  survivors for confidence. Keep the comparison cohort tied to vacancy start
  and use real elapsed time across daylight-saving transitions.
- Add per-room future-horizon and fallback controls. Defaults retain the safe
  stage duration plus 10 minutes and enable the stable-vacancy fallback for
  poor history as well as sparse history. Neighbour settings belong to that
  observed neighbour.
- Retain each robot's resolved stage, pass count, duration, forecast and
  adjacency evidence for preview, audit and dashboard. Recheck the vacancy
  gate after profile preparation and the durable checkpoint, before starting.
- Persist bounded missed-window summaries and deduplicated overdue notices.
  Closed windows are recorded even when the blocker never changes; downtime
  remains unknown. No notification changes settings or dispatches a robot.
- Show separate vacuum, mop and full-program completion, repeated mop-window
  expiry, and aggregate occupancy-source quality. The two dashboard copies
  remain identical. A synthetic [local preview](../../dashboard/overdue-preview.html)
  exercises the shipped evidence rows.

See the [migration guide](../migration-v1.18.0.md) for schema 19, new defaults,
notification thresholds and rollback requirements. Public IDs and existing
allocation priority are preserved.

## Compatibility

The running Core was checked read-only on 11 October 2026. The compatible test
pair is Home Assistant 2026.10.0 and pytest-homeassistant-custom-component
0.13.371. The official [stable feed](https://version.home-assistant.io/stable.json)
lists Core 2026.10.1, but the current test plugin pins 2026.10.0; this release
uses that supported pair rather than forcing incompatible package requirements.
Config, service and Repair schemas use Core 2026.10's Probatio APIs.

Local and CI pins now agree: Python 3.14.7, Core 2026.10.0, HA test plugin
0.13.371, pytest 9.1.1 (the existing documented no-deps override), pytest-cov
7.1.0, Ruff 0.17.0 and mypy 2.4.0. Official
[checkout](https://github.com/actions/checkout/releases/latest) and
[setup-python](https://github.com/actions/setup-python/releases/latest) remain
on compatible major v7; workflow permissions remain `contents: read`.

## Validation

Final local validation on 11 October 2026 passed:

- 548 pytest cases, 615 subtests, and 95.16% combined statement/branch coverage.
- 548 unittest cases.
- Ruff format/lint and strict mypy across 60 production modules.
- 34 Node dashboard tests, JavaScript syntax, per-module Python compilation,
  recursive compilation, release metadata and shipped JavaScript/icon parity.
- Synthetic browser review at a 360-pixel card width; the evidence rows wrap
  without horizontal clipping and identify fallback separately from confidence.

Windows pytest validation disables plugin autoload and explicitly loads
`pytest_asyncio.plugin` and `pytest_cov.plugin`, because the HA plugin imports
the Unix-only `fcntl` module. Ubuntu CI uses normal plugin loading.

The automated tests use isolated fixtures; they do not dispatch live robots.

## Deployment

Back up Home Assistant before installing: schema 19 requires the matching
pre-upgrade Store backup when rolling back to an older integration. Install the
exact `v1.18.0` tag through HACS only after the released commit passes CI, validate
configuration, and restart with both robots docked and error-free. Verify the
integration is loaded, its new settings are available, and the dashboard resource
uses `?v=1.18.0`. No Core upgrade or verification clean is required.
