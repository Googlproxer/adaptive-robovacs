# Adaptive RoboVacs v1.20.0

Released 31 October 2026.

## Changes

- Discover the separate Roborock dock by registry metadata and include its
  clean/dirty tank reports in consolidated, restart-safe water notifications.
- Sample cached reports five minutes after settled docking and hourly until
  washing or departure. One shared deadline timer serves all robots; routine
  snapshots never request device updates, start washes, or evaluate the house.
- Gate new mop work on dock water readiness. At each otherwise eligible
  scheduled occurrence, permit one checkpointed verification wash, shared across
  a multi-room run, to recheck potentially stale tank reports.
- Require observed washing and a healthy delayed snapshot before resuming.
  Failed checks skip mopping while vacuum work remains eligible. Washes do not
  produce cleaning credit, duration learning, or permanent room exclusions.
- Display last-reported tank conditions, snapshot time, and verification
  progress on the existing robot card. These reports are not measured levels.

## Compatibility and migration

Read-only checks on 31 October 2026 confirmed Core 2026.10.4 and Python 3.14.9
on the running instance. The official stable feed also reports Core 2026.10.4.
No Core update is included.

The existing compatible pins remain current: Home Assistant 2026.10.4,
pytest-homeassistant-custom-component 0.13.375, pytest 9.2.0, pytest-cov 7.1.0,
Ruff 0.17.3, and mypy 2.4.1. Official checkout v7.0.1 and setup-python v7.1.0
remain on compatible major-v7 pins with read-only workflow permissions.

Store payload schema is 21, retaining existing scheduler data; the Store
envelope remains version 1. Public entities keep their IDs and unique IDs.
See the [migration guide](../migration-v1.20.0.md) for notification migration,
verification behaviour, and deployment checks.

## Validation

Local validation on 31 October 2026 passed:

- 620 unittest cases and 620 pytest cases, with 95.26% combined statement/branch
  coverage against Core 2026.10.4 and Python 3.14.9.
- Ruff formatting/lint, strict mypy across 65 production modules, per-module
  and recursive Python compilation, and `git diff --check`.
- All 42 dashboard tests, dashboard JavaScript parity, and brand icon parity.
- Browser regressions: 10 passed and two intentional platform-specific skips,
  across Chromium, Android emulation, and WebKit, using two workers. The fully
  parallel local run encountered test-server connection failures; the bounded
  rerun passed.

On Windows, pytest ran with plugin autoload disabled and explicit
`pytest_cov.plugin` / `pytest_asyncio.plugin` loading because the HA pytest
auto-plugin imports Linux-only `fcntl`. The tests still use the pinned HA test
helpers. CI retains its normal Linux plugin loading. Windows asyncio and browser
checks require local loopback access.
