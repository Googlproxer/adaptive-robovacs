# Adaptive RoboVacs v1.19.1

Released 23 October 2026.

## Changes

- Reconcile robot and room dispatch-fault Repairs against durable scheduler
  faults. Delete obsolete issues after successful retries and when publishing
  scheduler status, including startup and refresh. Retain active faults and
  issues owned by other config entries or integrations.
- Treat a robot Repair whose fault and hold are already gone as successfully
  resolved. Repeated Submit actions can close the dialog without changing
  active work, unrelated holds, completion credit, or dispatching a clean.
- Preserve dispatch-fault Repairs when storage cannot be read safely; an empty
  fallback state does not prove the fault has cleared.

## Compatibility

Read-only checks on 23 October 2026 confirmed running Core 2026.10.2 matches
the [official stable feed](https://version.home-assistant.io/stable.json).
PyPI checks retain homeassistant 2026.10.2,
pytest-homeassistant-custom-component 0.13.373, pytest 9.1.1, pytest-cov 7.1.0,
and mypy 2.4.0. Refresh the local and CI Ruff pin to
[0.17.2](https://pypi.org/project/ruff/0.17.2/).
The documented pytest no-deps override remains necessary.
Python remains 3.14.8. Official checkout v7.0.1 and setup-python v7.1.0 retain
the compatible major-v7 action pins and read-only workflow permissions.

## Migration and deployment

No storage migration, settings reset, or entity ID changes are required.
Existing obsolete dispatch-fault Repairs are removed on the first status
publication after loading this version. Active Repairs continue through the
existing physical-state and configuration checks.

For deployment, publish the annotated `v1.19.1` tag and full GitHub Release
after validation, install that exact tag through HACS, validate Home Assistant
configuration, and restart while both vacuums are not cleaning. The frontend
is unchanged and requires no resource-version update.

## Validation

Local validation on 23 October 2026 passed:

- 583 unittest and pytest cases, with 95.18% combined statement/branch coverage.
  The new regressions reproduced stale Repair retention and failed Submit
  before the fix. They now verify owned-issue cleanup, repeated submission,
  unrelated-blocker and active-job preservation, status publication, and
  unreadable-storage protection.
- Ruff 0.17.2 formatting and lint, strict mypy across 63 production modules,
  per-module Python compilation, recursive compilation, and `git diff --check`.
- Release contract checks include identical dashboard JavaScript copies and
  root/integration icon parity. The frontend is unchanged.
- All 41 dashboard tests pass.

Windows pytest disables only the Home Assistant plugin (`-p no:homeassistant`)
because its runner imports the Linux-only `fcntl` module. The full unittest
suite also passes against Core 2026.10.2. Linux CI retains the normal plugin.
Windows async tests require local loopback socket access and use synthetic
robots; no real cleaning command was dispatched.

The reported live Repair was separately dismissed through Home Assistant's
Repair API after confirming no matching durable fault remained, then verified
absent from the active Repairs list. No runtime data is included here.
