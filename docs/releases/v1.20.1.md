# Adaptive RoboVacs v1.20.1

Released 1 November 2026.

## Changes

- Show an amber **⚠ Water needs attention** row immediately below robot Status
  when the latest stored water report contains a clean-tank, dirty-tank, or
  onboard-water fault. Include the action to take and the stored report time.
- Keep the warning visible independently of overall robot readiness and water
  verification progress. Retain previously notified faults while their evidence
  is unknown, and clear them after a healthy stored report.
- Preserve the existing scheduled sampling, notifications, verification washes,
  and dispatch rules. The display does not request fresh telemetry or a wash.

## Compatibility and migration

Read-only checks on 1 November 2026 confirmed running Core 2026.10.4 with no
Core update offered. The [official stable feed](https://version.home-assistant.io/stable.json)
also reports 2026.10.4. No live Core upgrade is included.

The compatible dependency pins remain current: Home Assistant 2026.10.4,
pytest-homeassistant-custom-component 0.13.375, pytest 9.2.0, pytest-cov 7.1.0,
Ruff 0.17.3, and mypy 2.4.1. Official checkout v7.0.1 and setup-python v7.1.0
remain on compatible major-v7 pins with read-only workflow permissions.

No Store migration, entity-ID changes, dashboard YAML edits, or new configuration
are required. Existing robot cards discover the warning after the integration
update and a browser refresh. The two shipped JavaScript copies remain identical.

## Validation and deployment

Local validation on 1 November 2026 passed:

- 627 unittest cases and 627 pytest cases, with 95.27% combined statement/branch
  coverage against Core 2026.10.4 using the existing Windows Python 3.14.7 venv.
  CI retains its Python 3.14.9 pin.
- Ruff formatting/lint, strict mypy across 65 production modules, per-module
  and recursive Python compilation, dashboard/icon byte parity, and diff checks.
- All 44 dashboard tests, including warning placement, robot scoping, cleared
  and unavailable states, cached-report wording, and keyboard details.
- Headless Chromium preview at 390px and 1100px: wrapped warning content,
  amber styling, keyboard navigation, and removal after a healthy report.
  The preview uses synthetic data and a minimal native-card stand-in;
  final live Home Assistant visual acceptance awaits deployment.

Windows asyncio checks required local loopback access. Pytest used explicit
coverage and asyncio plugins with automatic plugin loading disabled, as the
Home Assistant pytest auto-plugin imports Linux-only `fcntl`.
