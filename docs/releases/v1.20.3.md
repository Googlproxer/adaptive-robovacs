# Adaptive RoboVacs v1.20.3

Released 6 November 2026.

## Changes

- Reuse validated occupancy-history samples and their fingerprints during
  repeated progress checkpoints. Cache keys include every sample value,
  timestamp timezone and DST fold; in-place edits, replacement, pruning and
  clearing invalidate the affected history. Removed rooms leave the cache.
- Give every checkpoint fresh dictionaries and lists. Cached wire values are
  immutable, and a mutated prepared payload loses its validation shortcut.
  All remaining records and cross-record constraints are validated normally.
- Keep the complete existing Store payload and checkpoint frequency. Startup,
  schema migration and ordinary dictionary/JSON loads still validate all data.
  No Store schema, entity ID, configuration or dashboard migration is required.
- Encode Store JSON in an executor and request atomic writes. Confirm that the
  actual write hook completed before acknowledging a checkpoint or advancing
  the saved fingerprint. Home Assistant can log and consume a write error;
  such a return is now rejected, including read-only and shutdown-deferred saves.
- Drain a cancelled write before accepting another checkpoint, preventing an
  older filesystem operation from replacing a newer checkpoint out of order.
  Invalidate the saved fingerprint after any failed/cancelled save, so an
  unacknowledged replacement cannot suppress a retry of unchanged current state.
  Failed checkpoints remain eligible for retry; native robot observations,
  occupancy, Party Mode, observe-only and recovery rules retain their authority.
- Extend the synthetic cleaning benchmark with an untimed regression check:
  repeated progress updates must not decode unchanged occupancy samples, and
  every required progress checkpoint must still be written.

## Compatibility and validation

Requires Home Assistant 2026.11.0 or newer; HACS and the validation environment
use this minimum. The read-only 6 November check found Core 2026.11.0 running
and offered by the official stable feed. Replace the outdated external fixture
plugin with a small repository-owned runtime fixture using real Core registries
and config entries. Component Stores remain real filesystem Stores. The full
test suite and benchmarks now run directly on Core 2026.11.0, including the
private write-hook compatibility contract. No older-Core compatibility layer
or special pytest installation is retained.

Refresh Ruff to the compatible 0.17.4 patch in requirements and CI. The other
validation pins remain current; official action major versions and read-only
workflow permissions remain unchanged.

See [performance documentation](../performance.md) for measurement boundaries
and before/after results. Validation includes the full Python suite and coverage
gate, unittest, compilation, Ruff, strict typing, dashboard tests, shipped-file
parity and real Core 2026.11.0 Store contracts.

Final local validation passed 659 pytest cases with 95.42% combined statement/
branch coverage, the same 659 unittest cases, Ruff formatting/lint, strict mypy
across 66 production modules, both compilation checks, and all 44 dashboard
tests. The final cleaning budget check and the broader medium backend smoke
benchmark passed without budget warnings. Dashboard and icon copies remain
byte identical. CI has been updated for the same Core 2026.11.0 environment.

The 50-sample Core 2026.11.0 comparison reduced median active-evaluation time
from 62.6 ms to 33.3 ms (46.7%) and 16 sequential timer updates from 501.1 ms
to 189.2 ms (62.2%). Their p95 values were 72.9 ms and 218.8 ms respectively,
within the cleaning benchmark's advisory budgets. The untimed cache regression
check retained all 16 required checkpoints with zero unchanged occupancy
sample decodes. These timings exclude disk/executor latency and live devices.

## Deployment

This release is published without deployment. No HACS installation, integration
reload or Home Assistant restart is part of this release operation.

For a later deployment, require successful CI and install the exact v1.20.3 tag
through HACS. Validate configuration and confirm both vacuums are idle before
restarting Home Assistant. Verify the integration loads on v1.20.3.
The v1.20.2 tag is the code rollback target; the Store wire format is unchanged.
