# Adaptive RoboVacs v1.17.0

## Recovery behavior

- An interrupted room clean caused by a physical robot error remains incomplete.
  When the robot has returned to its dock, reports a clear error state, and its
  detailed status is ready for three uninterrupted minutes, the saved room
  recovery clears automatically. The unfinished stage may then enter normal
  scheduling again. The robot may serve other eligible rooms after the original
  attempt has been safely detached.
- Simple paused and robot-error holds are rechecked automatically after the
  same ready-dock interval. Legacy interrupted checkpoints are abandoned only
  when their ownership can be safely checked. Cleaning history is never
  credited by clearing a hold.
- Pre-start adapter preparation failures retry after 2, 5, 15, then at most
  30 minutes. Each retry is persisted and still passes all normal dispatch
  gates, including fresh occupancy and profile checks. A start request that
  remained continuously docked without any observed clean gets one retry after
  three minutes of ready docking. A second failed confirmation requires review.
  A changed physical state after the start request is treated as an uncertain
  outcome and remains held.

## Manual review and reset options

- Missing, stale, or ambiguous room mapping and uncertain physical starts still
  require manual review. An unsupported cleaning program, pass count, or
  profile stays held until it is compatible or the user selects a Repair reset.
- The relevant room Repairs offer separate room and robot cleaning-settings
  resets, with explicit options to discard a saved pending attempt. They check
  a proposed default against the affected vacuum before saving. Room cadence,
  daily window, enablement, and occupancy settings are retained. No reset
  starts a clean.
- Invalid scheduler Store data continues to disable dispatch. Its Repair can
  back up and verify the exact invalid payload under a separate Store key,
  replace this integration's state with defaults, and leave the scheduler in
  observe-only mode. It requires explicit confirmation and does not touch
  Home Assistant recorder history or robot state.

## Compatibility and deployment

The Store version is unchanged. Existing safe pre-start faults receive an
initial retry deadline during migration; old start-confirmation faults stay
manual because their original physical evidence cannot be reconstructed.
No public entity or unique ID changes. Fault attributes now include the
retry attempt count and next retry time.

The running Home Assistant Core is 2026.9.2. The available stable update is
2026.9.3; this release updates the CI acceptance pins to Home Assistant
2026.9.3 and pytest-homeassistant-custom-component 0.13.366. This does not
upgrade the live Home Assistant host. Install v1.17.0 through HACS after the
release and successful CI. Per the deployment request, do not restart Home
Assistant. The installed code remains inactive until a later restart.
